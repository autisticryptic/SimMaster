# 蜂窝 IMS 地址族策略

## 生产策略：所有线路统一完整兜底

蜂窝 IMS 固定使用 **IPv4v6（双栈）→ IPv6 → IPv4**。不再提供线路级的单族选择、自定义顺序或自动/手动地址族开关。策略不依赖当前 SIM，换卡不会继承上一张卡的 IPv6-only 限制。

- 已移除 `cellular_ims_ip_families`、`cellular_ims_ip_families_auto` 及对应 `volte_*` 配置字段、读写方法和前端契约。
- 已移除 `/api/cellular-ims/lines/{line_id}/ip-families` 与旧 `/api/volte/lines/{line_id}/ip-families` 写入口；旧客户端不能借这些入口改策略或断开会话。
- 加载数据库时，在完整配置校验通过后，以事务仅删除所有线路 JSON 中的上述四个字段。保留其他字段、其他表以及未涉及线路的时间戳；校验或写入失败则回滚。旧配置导入后也不能重新启用这些字段。
- `ImsConnectionPlan::default()` 是唯一生产计划来源；运营商目录的 `ip_stack` 元数据不能缩减它。普通数据 APN 和 VoWiFi/ePDG 的协议栈配置是不同功能，不在本次移除范围内。

## 兜底的执行边界

1. 正常承载建立失败后，按计划继续单族尝试；网络明确仅允许某族时，保留有界、去重的指定族重试。
2. 双栈承载只获得一个地址族，仍是合法的成功承载，不为凑齐双栈并行创建额外 PDN。
3. 当前承载建立成功后，P-CSCF/SIP 在该承载已授予的地址中尝试。此版本**没有新增“SIP失败后重新建立另一地址族承载”的外层循环**，也不将认证拒绝当作无限重试理由。
4. 基带故障、SIM/owner变化、清理未确认必须停止本轮操作，保留归属记录。这是故障安全边界，不是永久禁用某个地址族；后续获准建立连接时仍从完整默认计划开始。
5. 显式 `mm-ims-profile-lease` 维护探针仍可选择一个地址族，但只作用于隔离探针。即使收到网络强制族错误，也不得扩大为第二次承载；不写生产线路配置。

## QCM410 固件风险与本次补强

历史新卡测试中，IPv4 Connect 后约 0.37–0.40 秒发生 `dhcp_client_mgr.c:263` fatal，共四次，最后 QMI 控制口消失。`6c6fcfd` 之后的 IPv6 注册/续期成功不能证明 IPv4 固件问题已修；初始双栈请求也可能触及 IPv4 路径。

本次修复两个确定的应用层缺口：

- 清理或代次检查失败时，保留原始 `BasebandWedged` 分类，避免将其覆盖为普通绑定丢失；未知资源仍保留。
- 在 MM 准入/代次提前返回之前记录物理线路故障，避免故障自身引起的失联抹掉冷却。注册状态仍受代次约束，不向新卡发布旧会话结果。只有显式手工重试可绕过临时冷却，其他自动入口不能间接绕过。

这些补强**不是固件根因修复，也不保证首次 IPv4 激活绝不崩溃**。现有冷却是进程内物理线路状态，不宣称已实现跨进程、跨普通数据业务的持久硬件熔断预算。发生新的 fatal 时，必须停止重复激活、保存连接/清理/内核时序，确认控制口及旧归属恢复后再决定受控恢复；不可盲删账本、永久禁 IPv4，或直接写有整机复位风险的 remoteproc 开关。

## 默认双栈实际仅授予IPv6的归属补强

首轮恢复默认策略后，410的MM成功返回IPv6，但原P-CSCF分离证明仅允许profile定义为`IPV6`，导致`IPV4V6`定义的合法单族授予被拒绝。修复按实际MM授予与AT地址证据处理：MM无IPv4、目标只有一IPv6行、同CID/同前缀、完整CGPADDR匹配、其他活动上下文分离、两次完整快照一致。CGPADDR仅允许唯一IPv6及可选的`0.0.0.0`未授予占位；实际IPv4伴随、双行歧义或定义改变仍拒绝。不通过改回IPv6-only解决此问题。

显式`inspect-uncreated/retire-uncreated`只处理创建进程死亡、未记录任何已创建资源、原完整库存仍一致的旧创建意图。要求同boot/owner/SIM、完整双快照、源记录至少静置120秒和匹配token；仅归档元数据，自动恢复仍阻断`Creating`。它不是忽略不确定写入的通用清账按钮。

代码回归覆盖：所有线路旧字段迁移、事务回滚/幂等性、旧 HTTP 入口失效、默认三族顺序、网络强制族去重、诊断预算、清理包装保留故障、先失联后报告故障。部署验收需另行记录最终制品哈希、正式服务注册、实际承载族、旧字段消失及新内核故障计数；不能用离线测试或探针成功代替正式服务注册。

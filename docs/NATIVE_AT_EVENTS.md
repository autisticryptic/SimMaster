# Native AT 事件处理与事务边界

默认 MM 不变；本页增强不代表 native 已通过实机验收，也不会在 MM 运行时自动接管串口。

## 已实现

- 所有 AT 命令、USSD、短信提交及原生被动事件读取共用 `at_session` 的同一会话互斥锁。
  不另起一个抢读字符设备的线程。
- 已知 URC 与无关命令响应分流。注册查询等同名响应仍属于查询；拨号/接听的 `NO CARRIER`、
  `BUSY`、`NO ANSWER` 是失败终结码，但异步呼叫结束不会终止正在执行的 `AT+CSQ` 等查询。
- 命令前排空会保留完整 URC 提示，而不是全部丢弃；普通命令/短信提交期间的 URC 同样收集。
- CMGS 的 `>` 只在帧边界识别，不会被 USSD 文本里的大于号提前触发。
- 单帧缓冲上限 32 KiB、普通响应上限 1 MiB、一次排空/事件读取最多 64 次有界读，
  命令仍有原先的截止时间；噪声/未终止行不能无限占用内存或物理门。
- URC 只投影为七个可合并 bool 提示，不保存或广播号码、短信正文、USSD 文本、SIM 身份。
  这不是原始 modem 日志出口。

## 业务事件订阅与原生短信调度

存在且启用的 native 线路通过同一个有界 AT pump 每秒读取提示；明确配置的 AT 口可为
语音/驻网观察而读取，短信开关不再吞掉其他业务事件。没有配置 AT 口的 QMI-only 设备不探测猜选串口。

- 64 项有界广播分别唤醒通话监视器和注册/线路核对；消费者落后时收到 Lagged 并重新核对，
  不把缓存提示当成注册成功或电话已接通。
- 空闲 native 通话轮询降为 15 秒兜底；有活动通话时保留原有结束判定的快速核对。
  注册/线路保留 60 秒兜底；MM 的原调度不变。
- Web 事件总线仅发布 `modem.native_observation` 的 bool 提示或事件丢失计数，
  不发布原始 URC、号码、正文或 SIM 身份。

短信仍要求设备启用接收、线路允许接收且 IMS 没有取得接收权：

1. 每秒发起一次被动 `AtPoll`。不发送 AT 命令；打开口时仍需常规 termios 配置。
2. 沿 `NativeDevice::command` 的物理操作门执行，`NativeIo` 在前后核对端口归属与代次。
3. `+CMTI` 等提示只请求一次既有存储扫描；扫描重新检查准入，再执行初始化/读取。
4. 仍由共享持久化入口、内容指纹去重和删除前 SIM/索引/PDU 核对决定接收及清理。
5. 保留每 15 秒完整扫描，兼容 URC 未开启、输入分片在事务边界丢失或提示遗漏。

未启用 `sms_reception_enabled` 的 native 设备不会消费短信存储；已启用线路的语音/驻网观察
可读取其显式 AT 口，独立于短信准入。禁用/不存在的线路不运行该事件 pump。
命令和被动读取发生错误时不自动重发 SMS，也不停止 MM、改 APN、猜端口或恢复未知 receipt。

## 尚未完成

- 当前广播合并事件提示并唤醒权威状态核对，不把无关联 URC 直接转换成业务成功。
- 语音的权威状态仍来自 `CLCC`，事件减少空闲轮询但不替代必要的确认。
- 直接 `+CMT` / `+CDS` 的 PDU 会从无关命令响应中隔离，但目前只触发存储核对，
  **不等于直接短信或送达报告已被完整消费**。当前接收配置仍选存储通知模式。
- 不能无歧义区分所有同名查询响应与 URC；没有静默猜测新的协议归属。
- 端口重枚举后仍依赖原有 fail-closed owner/generation 边界；无自动换端口重连。
- 真实 native SMS、来电、USSD、掉线与长期运行仍需独立设备验证。

## 验证

`at_urc::tests` 测分类、同名前缀、拨号终结码、PDU 隔离、敏感信息及洪泛有界性。
`at_session::tests` 使用 Unix socket pair 模拟端口，测试 URC/回复交错、分片、无写被动读取、
排空保留、CMGS 提示/reference 和缓冲上限；不访问真实 modem。
`backends::messages::tests` 验证只使用显式 AT 口和禁用接收时不读取。
三组 Rust 测试仅在 GitHub Actions 编译执行，Python 守卫保证准入与过滤器不会退化。

参考思路与许可证边界见 [原生后端审计](NATIVE_BACKEND_AUDIT_2026-09-24.md)。

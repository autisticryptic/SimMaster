# 1.1.4-beta1：既有 IMS 修复与发布流程收尾

状态：**候选验证版；尚未标记双注册实机修复完成**。

## 已完成的代码改动

- 保持 1.1.4 主版本，仅使用用户指定的 beta1 后缀，不生成自动递增正式版或 build-N 版本。
- Beta 后缀强制 pre-release / 非 latest，适用于 push 和手动构建；手动选择 latest 不能把 beta 误标正式版。
- 初始、认证、refresh 和注销 REGISTER 的 Supported/Require 规范化为各一行，保留安全协商及认证字段。
- 记录最终 REGISTER 的 outbound 能力及响应协商证据；不会把仅回显 reg-id 当成双流协商成功。
- 保留共享实例标识、各接入独立 reg-id/绑定/租期，以及每条线路的注册准入协调。
- 保留已实现的受保护 refresh 事务、网络挑战处理及失败回滚，不恢复固定 120 秒测试间隔。
- 分离已协商的多流能力和即时保活验证；短暂保活等待不能让已建立双注册被策略误拆除，新建第二流仍需完整验证。
- 安全协商候选通道保留原 outbound 要求；先验证并发布新绑定，再退休旧流，失败不提前提交安全上下文或记录成功。
- API/UI 区分“尚未协商”和“当前成功响应未接受多流”；增加每路绑定有效期/传输验证的脱敏状态，不把两路开关或缓存状态当成双注册证据。
- 新增蜂窝先注册、VoWiFi 后注册、两路交替续期，以及保活等待、候选安全通道和当前拒绝状态生命周期的回归覆盖。
